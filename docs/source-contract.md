# 调度看板

页面按 pending、team-a、team-b 三个泳道显示实际 HTML5 可拖动卡片。两张“装卸”来自不同航次，查验卡带前置作业键。正常拖放触发浏览器确认框，通过后更新业务归属与版本。

占用名额按钮降低容量，满载时拖放被拒绝。现有查看器只读卡片。可继续扩充折叠泳道、虚拟占位和时段确认场景；新增自动化不得直接执行页面内数据修改来伪装拖放成功。门户的业务数据保存在本地来源服务中，关闭或重新打开浏览器不会撤销已接受的写入；页面 data-saved 可用于等待门户自身保存结束。状态接口只供门户运行，自动化不得直接调用它代替界面操作。

## 页面事实与自动化边界

- 卡片身份由 `data-key`、`data-voyage`、`data-version` 共同确定；标题只用于展示，重名卡不得按标题匹配。
- 归属以卡片所在的 `data-lane` 为准；目标泳道折叠时不渲染接收区，必须先执行页面的“展开”点击。
- 待分派栏超过一定数量后使用虚拟窗口，只渲染可见卡片；滚动会由门户重建节点。自动化必须先滚动到卡片真实可见，再开始拖放，拖放期间不得再触发列表滚动。
- 泳道内的灰色“虚拟占位”不是接收区；拖到那里只会得到 `invalid-drop`，不能当成已分派。
- 落点结果只认页面 `#status` 的 JSON 与 `data-saved` 完成标记。`accepted` 才代表门户接受；`rejected`、`blocked`、`invalid-drop` 与 `needs-slot` 都不是提交成功。
- `needs-slot` 时页面弹出时段选择，必须选择时段并按确认；未选择就关闭视为未提交。
- 目标和源泳道容量、卡片归属都可能在预览与执行之间被人工改变；执行前必须重新读页面。

## 分派计划与恢复

`src/dispatch.mjs` 提供 `previewPlan`、`executePlan`、`recoverPlan`：

- 预览按业务键找到页面卡片，核对航次、当前泳道与版本，输出可执行项、冲突项与批次。
- 依赖取自计划内的 `depends` 或页面 `data-depends`；前置未成功时后继记为 `blocked`，无关卡继续。
- 单卡失败或门户拒绝只影响该卡及其依赖者，不阻止其他可执行卡。
- 执行后的 `attribution` 来自执行结束时的页面快照；恢复核对 `recoverPlan` 只读页面最终归属，人工已派走的卡保留页面结果，不拉回。
- 每个动作都把页面状态、确认框原文、滚动与落点读回写入证据列表。

## 演练门户扩展

`portal/app.js` 的本地演练门户还包含：team-b 初始折叠、待分派栏虚拟滚动、`data-placeholder` 虚拟占位、V6 系列卡需补选作业时段、`data-compete` 占用名额按钮。自动化不得调用 `/state` 或改写页面变量来绕过上述行为。
